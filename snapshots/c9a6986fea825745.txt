Validators secure the network
A FLOP validator stakes FLOP to build blocks of inference proofs, store model weights in the data-availability layer, and govern the network. The active set shares 10% of block rewards.
Key points
Build blocks from miners' proofs of inference.
Store and serve model weights in the data-availability layer.
Govern the network by voting on FLOP Improvement Proposals.
Validator set
1,000
Top 1,000 by bonded self-stake among validators passing an on-chain service-level check, one equal seat each. A seat changes only when outbid by a margin, on a failed service-level check, or on exit. Ratified; not yet live in the runtime, which still rotates monthly and does not yet enforce the cap.
Validator reward
10%
The active set shares 10% of block rewards in equal seats: half is liquid, half is bonded and unlocks linearly over about ten years (ratified; the runtime still pays it fully liquid). The transaction-fee leg is still interim.
FIP approval
⅔
Most FLOP Improvement Proposals need two-thirds of the active validator set.
Protocol brief
What to know
What validators do
Validators build blocks that carry a commitment to each proof rather than the proof bytes, and they store the model weights that agents and miners rely on in the data-availability layer.
Blocks carry a commitment to each proof, not the proof bytes; the evidence itself lives in the data-availability layer.
Validators hold model weights in the DA layer so sessions can be served.
The active validator set shares 10% of block rewards. Transaction fees are not burned: the block author receives the whole fee.
Staking, selection, and slashing
Becoming a validator requires staking FLOP. The ratified rule re-selects the set every session as the top 1,000 by bonded self-stake among validators that pass an on-chain service-level check (block authorship, finality participation, data-availability audits and verification duty — no GPU needed). Stake above the 1.2M floor buys rank only, never a larger reward share, and there is no forced rotation. This is not yet live in the runtime: the running network still rotates the set every 30 days on work and performance metrics.
Validator stake is self-stake only; there is no delegated stake.
Publishing a dishonest block risks draconian slashing and a permanent ban.
A seat changes only when a challenger outbids it by a margin, when it fails the service-level check, or when its validator exits. Each session, a finality committee of 100 is drawn uniformly from the live seats.
Governance
Validators are the guardians of the network. On a successful FLOP Improvement Proposal (FIP), the active set votes, and in most cases two-thirds must approve before implementation begins.
FIPs are the on-chain governance mechanism.
Most changes need ⅔ of the active validator set to approve.
Through the first halving, only the FLOP Foundation may submit a FIP.
Execution path
How it works
01 / Stake
Stake FLOP to enter the queue for the capped 1,000-validator set.
02 / Build
Bundle miners' proof hashes into one-second blocks.
03 / Store
Keep model weights available in the data-availability layer.
04 / Govern
Vote on FIPs; most need two-thirds of the active set.
